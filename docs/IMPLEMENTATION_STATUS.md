# وضعیت پیاده‌سازی فلزنگار

## آماده در سورس فعلی
- Monorepo مستقل با دو Workspace مجزا برای Astro و Next.js.
- رابط نمایشی Astro با RTL، Vazirmatn، Light/Dark، ناوبری ماژول‌ها، نمودارهای برداری، جدول معاملات، واکنش‌گرایی موبایل و تعاملات نمایشی محلی.
- داده‌های نسخه نمایشی کاملاً نمونه و بدون اتصال به دیتابیس؛ فرم‌های نسخه Pages فقط در حافظه مرورگر عمل می‌کنند.
- Workflow برای Build و انتشار فقط پوشه `apps/web/dist` در GitHub Pages.
- مدل PostgreSQL/Prisma برای مشتریان، کاربران/Session، محصولات، قیمت‌ها، معاملات، دفتر وزنی، دفتر مالی، پرداخت‌ها، تحویل‌ها و Audit Log.
- Better Auth با Email/Password، نقش‌های admin/user و غیرفعال بودن ثبت‌نام عمومی به‌صورت پیش‌فرض.
- APIهای پایه برای مشتری، ارز، محصول، قیمت دستی، معامله، پرداخت، تحویل، خلاصه مدیر، خلاصه مشتری و گردش حساب مشتری.
- سرویس‌های پایه ثبت معامله/پرداخت/تحویل با Decimal، تراکنش Prisma و Audit Log.
- برگشت سند معامله با سند معکوس و ثبت علت؛ حذف فیزیکی سند در مسیر عادی وجود ندارد.
- محدودسازی API مشتری به شناسه Customer متصل به Session.
- Docker Compose توسعه برای PostgreSQL و راهنمای اجرای محلی.
- پروژه در Repository عمومی `rasoolbahadran-stack/metal-ledger` قرار داده شده است؛ وضعیت فایل‌ها و Workflow از Actions باید مستقلاً کنترل شود.

## هنوز آماده بهره‌برداری مالی نیست
- GitHub Pages تا فعال‌سازی Pages با Source برابر GitHub Actions و موفقیت Workflow منتشرشده تلقی نمی‌شود.
- وابستگی‌های npm در محیط توسعه قبلی نصب نشدند؛ تلاش نصب به Timeout خورد. بنابراین Build و تست TypeScript/Prisma/Next/Astro در آن محیط تأیید نشده‌اند.
- PostgreSQL واقعی راه‌اندازی نشده و Migration اجرا نشده است. Docker Compose صرفاً برای اجرای محلی آماده است.
- UI Astro هنوز به API Next متصل نیست؛ نسخه Pages صرفاً Showcase است.
- صفحه‌های مدیریتی سروری فقط پایه‌های داشبورد، مشتریان، معاملات و محصولات را دارند؛ CRUD کامل و همه فرم‌های مدیریتی هنوز ساخته نشده‌اند.
- چرخه ساخت حساب مشتری پیاده‌سازی اولیه دارد و باید پس از نصب وابستگی‌ها با نسخه واقعی Better Auth و PostgreSQL آزمون شود.
- برگشت سند برای پرداخت و تحویل کامل نشده؛ برگشت معامله پیاده‌سازی اولیه دارد.
- Idempotency-Key، retry برای serialization conflict، Rate Limit، صفحه‌بندی کامل، فیلترهای پیشرفته و کنترل جامع دوباره‌فرستی سند تکمیل نشده‌اند.
- API قیمت فقط ثبت دستی را پشتیبانی می‌کند؛ Provider خارجی انتخاب یا متصل نشده است.
- گزارش PDF رسمی چندصفحه‌ای فارسی با فونت جاسازی‌شده پیاده‌سازی نشده است؛ فقط قابلیت Print مرورگر در UI نمایشی وجود دارد.
- آپلود امن رسید، ذخیره‌سازی خصوصی، اسکن فایل و سیاست نگهداری/دسترسی فایل پیاده‌سازی نشده‌اند.
- تست End-to-End، آزمون رقابت/هم‌زمانی، تست IDOR/CSRF/CORS و ارزیابی امنیتی مستقل انجام نشده‌اند.

## تست‌های سورس
تست‌های واحد پایه برای محاسبه اثر معامله، پرداخت و مانده مالی در `apps/api/tests/ledger.test.ts` نوشته شده‌اند؛ به علت نصب‌نشدن وابستگی‌ها، تست‌رانر پروژه اجرا نشده است. بررسی دستی سه حالت قالب‌بندی دقیق اعداد در `formatFaNumber` موفق بود و ۳۸ فایل TypeScript/TSX از نظر تبدیل نحوی TypeScript بررسی شدند (صفر خطای نحوی). `node --check` برای اسکریپت رابط کاربری و پیکربندی Astro نیز موفق بود. این بررسی‌ها جایگزین Typecheck، Build یا تست یکپارچه نیستند.

## قواعد مالی نیازمند تأیید کسب‌وکار
- ارز باید در تنظیمات CurrencyUnit تعریف شود؛ پیش‌فرض ریال/تومان تعیین نشده است.
- دقت اعشار ارز (۰ تا ۴) هنگام تعریف ارز مشخص و هنگام ثبت سند Snapshot می‌شود.
- دقت وزن بر اساس محصول کنترل می‌شود؛ برچسب عیار/خلوص محصول صرفاً توصیفی است و هنوز در محاسبات اثر ندارد.
- فروش و تحویل بیش از مانده وزنی، در سرویس پایه رد می‌شود. این سیاست محافظه‌کارانه و موقت است و باید تأیید شود.
- تحویل فیزیکی در مدل فعلی فقط دفتر وزنی را تغییر می‌دهد، نه دفتر مالی.
- مالیات، کارمزد، اجرت، عیار، خلوص و مبنای قیمت هنوز مدل تجاری نهایی ندارند.
