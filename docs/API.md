# قرارداد اولیه API

تمام مسیرهای زیر در Next.js و با احراز هویت سمت سرور اجرا می‌شوند. داده‌های مالی فقط از طریق سرویس‌های دامنه ثبت می‌شوند. واحد ارز و دقت اعشار از جدول CurrencyUnit خوانده می‌شود؛ API ثبت سند اجازه تعیین مقیاس اعشار دلخواه در هر درخواست را نمی‌دهد.

## سلامت سرویس
- `GET /api/health` — بررسی زنده اتصال به PostgreSQL؛ در صورت قطع/تنظیم‌نبودن دیتابیس پاسخ `503` برمی‌گرداند.

## احراز هویت
- `POST /api/auth/sign-in/email` — ورود ایمیل/گذرواژه (Better Auth)
- `POST /api/auth/sign-out` — خروج
- `GET /api/auth/get-session` — دریافت Session
- ثبت‌نام عمومی غیرفعال است؛ حساب مشتری را مدیر ایجاد می‌کند.

## مدیریت مدیر
- `GET|POST /api/customers` — فهرست/ایجاد پرونده مشتری؛ امکان ساخت حساب ورود با ایمیل و گذرواژه
- `GET|POST /api/currencies` — فهرست/تعریف ارز و تعداد رقم اعشار مجاز
- `GET|POST /api/products` — فهرست/تعریف محصول
- `GET|POST /api/prices` — مشاهده و ثبت قیمت دستی (فقط با ارز فعال و تعریف‌شده)
- `GET|POST /api/trades` — فهرست و ثبت خرید/فروش
- `POST /api/trades/:id/reverse` — برگشت سند معامله با علت اجباری
- `POST /api/payments` — ثبت دریافت/پرداخت وجه
- `POST /api/deliveries` — ثبت تحویل فیزیکی کالا
- `GET /api/admin/summary` — خلاصه داشبورد مدیر

## پرتال مشتری
- `GET /api/me/summary` — خلاصه حساب فقط برای مشتری واردشده
- `GET /api/me/statement?from=YYYY-MM-DD&to=YYYY-MM-DD&productId=...` — ریز گردش حساب و مانده افتتاحیه

## قواعد امنیتی
- مسیرهای مدیریت نقش `admin` را سمت سرور بررسی می‌کنند.
- مسیرهای مشتری، `customerId` را فقط از Session معتبر می‌خوانند؛ مشتری مجاز نیست شناسه حساب را در Query یا Body تعیین کند.
- ورودی‌ها با Zod اعتبارسنجی می‌شوند.
- ثبت اسناد در تراکنش PostgreSQL انجام می‌شود و ردیف Audit Log در همان تراکنش نوشته می‌شود.
- پاسخ‌های مشتری شامل اطلاعات مشتری دیگری نمی‌شوند.

## نکات تکمیلی پیش از بهره‌برداری
این قرارداد، نسخه اولیه است. Idempotency-Key، صفحه‌بندی کامل، Rate Limit، فیلترهای پیشرفته، گردش کامل اصلاح پرداخت/تحویل و اتصال Astro به API باید قبل از Production تکمیل و تست شوند.
